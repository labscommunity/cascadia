# FlashInfer: Customizable Attention Engine for LLM Serving (arXiv:2501.01005)

**Year / venue:** 2025, MLSys 2025.
**Headline claim:** 29-69% inter-token-latency reduction vs PyTorch compilation backends, 28-30% latency cut for long-context, 13-17% for parallel generation. Integrated in vLLM, SGLang, MLC.
**Mechanism:** Three layers. (1) *Block-sparse + composable KV-cache format* — instead of a single contiguous tensor or paged blocks, FlashInfer represents the KV-cache as a sparse hierarchy where prefix-shared, page-managed, and ragged regions can coexist; one attention kernel handles all of them via metadata. (2) *JIT-compiled customizable attention template* — the attention kernel is generated per-shape from a Triton-like template, not a one-size-fits-all binary. (3) *Load-balanced scheduling* compatible with CUDAGraph for low launch overhead.

**Intel applicability:** MEDIUM. The *concepts* (composable KV layouts, scheduling-aware kernel selection) are gold and apply directly to OpenVINO's PagedAttention. The *implementation* is CUDA + Triton and ports require a non-trivial rewrite. There is no equivalent JIT attention generator for Intel GPUs today (OV uses a fixed kernel set).

**Implementation cost:** LARGE for a full port. SMALL if we adopt only the *composable KV layout* idea — letting a single sequence's KV-cache mix paged blocks (for the suffix) with a contiguous block (for a hot prefix) is a memory-management refactor in tahoma's worker, not a kernel rewrite.

**Open hypothesis it generates for us:** A composable KV-cache layout that keeps the hot system-prompt prefix in a single contiguous buffer (max coherence, no indirection) while paging the dynamic suffix gives a measurable prefill speedup on Intel iGPU because OV's matmul prefers contiguous K. Hypothesis: 1.15-1.25x prefill speedup vs full paging on alpha when system prompts are >256 tokens. Cheap to test once tahoma has paged KV at all.
