# PagedAttention / vLLM: Efficient Memory Management for LLM Serving (arXiv:2309.06180)

**Year / venue:** 2023, SOSP 2023.
**Headline claim:** 2-4x throughput vs FasterTransformer/Orca at equal latency. Greater wins at long sequences and large batch.
**Mechanism:** OS-style paging applied to KV-cache. Each sequence's KV is stored in fixed-size *blocks* (e.g. 16 tokens worth) with a per-sequence "block table" that maps logical positions to physical blocks. This eliminates internal fragmentation (no need to over-allocate per-sequence slots), enables KV sharing for branch decoding (multiple completions of the same prompt point at the same prefix blocks via copy-on-write), and lets the scheduler swap blocks to CPU under memory pressure. The attention kernel takes the block table as input and reads non-contiguously.

**Intel applicability:** HIGH. The *idea* is universal; the cost is implementing the gather-style attention kernel. OpenVINO 2024.5+ has a `PagedAttention` operator for Intel CPU/GPU/NPU — Intel is already on the bus. Tahoma's worker just needs to allocate the block table and feed it through.

**Implementation cost:** MEDIUM. The block allocator (per-sequence reference-counted blocks, CoW for prefix sharing) is non-trivial. The verification path needs to handle the block-table format. ~1500-2000 lines of careful code, but well-trodden — vLLM and SGLang are good references.

**Open hypothesis it generates for us:** PagedAttention's biggest win is at *large batch + long context*. On Intel Lunar Lake (alpha) the practical batch is ≤4 and contexts are ≤8K, so the absolute win may be smaller (~1.3-1.5x throughput vs naive contiguous KV). On Battlemage (charlie) at batch 8-16 it should be closer to the published 2-3x. But the unlock is *enabling prefix sharing* — tahoma's pipeline-parallel multi-stage architecture can use CoW-shared system-prompt KV across sessions, which is a strict prerequisite for any future multi-tenant serving.
