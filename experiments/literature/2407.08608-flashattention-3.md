# FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision (arXiv:2407.08608)

**Year / venue:** 2024, NeurIPS 2024.
**Headline claim:** 1.5-2.0x over FA-2 in FP16 (740 TFLOPS, 75% utilization on H100). FP8 reaches 1.2 PFLOPS with 2.6x lower numerical error than naive FP8 attention.
**Mechanism:** Three Hopper-specific kernel techniques. (1) *Asynchronous warp specialization*: dedicate some warps to TMA loads, others to tensor-core matmuls, others to softmax — they pipeline through producer-consumer queues in shared memory. (2) *Inter-stage interleaving*: overlap the matmul of one block with the softmax of the previous block. (3) *FP8 with block quantization + incoherent processing* (Hadamard rotation à la QuIP) to control outlier-induced quantization error.

**Intel applicability:** LOW for the *specific* implementation — TMA, warp-specialization, and Hopper-style FP8 tensor cores are NVIDIA-specific. MEDIUM for the *concepts*: (a) producer-consumer pipelining between async copy and matmul exists on Intel Xe2 (it's the equivalent of `cp.async`), but is not exposed in user-level OpenVINO yet; (b) the FP8 + Hadamard pre-rotation idea generalizes — Battlemage has FP8 support in tensor units, so a FP8-attention with Hadamard pre-mixing would translate.

**Implementation cost:** LARGE if we want a full Intel-native FA-3 equivalent (would require OneDNN / Level Zero kernel work, not in tahoma scope). SMALL if we just want to use the *Hadamard rotation* part as a numerical preconditioner on top of OV's existing INT8 SDPA — that's a few matmul fuses.

**Open hypothesis it generates for us:** Apply Hadamard rotation to Q, K, V before INT8 quantization in OV's SDPA. Hypothesis: this reduces post-attention error by ~2x (matching the FA-3 paper's report for FP8) and lets us run W4A8KV8 attention on Battlemage with negligible perplexity impact. Worth running on charlie with Llama-3-8B.
