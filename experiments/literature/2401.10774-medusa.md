# Medusa: Simple LLM Inference Acceleration with Multiple Decoding Heads (arXiv:2401.10774)

**Year / venue:** 2024, ICML 2024.
**Headline claim:** 2.2x speedup (Medusa-1, frozen backbone) to 2.3-3.6x (Medusa-2, joint fine-tune). No quality loss in greedy / typical sampling.
**Mechanism:** Bolt N small MLP "draft heads" onto the final hidden state of the base LLM, each predicting position +k for k=1..N. Each head produces top-K candidates → Cartesian product yields a tree of candidate continuations → tree-attention mask verifies all paths in a single forward pass of the base LLM. Crucially: no separate draft model — the heads are tiny (~1% of params), share base model state, and run on the same accelerator. Tree attention is the only non-trivial kernel addition.

**Intel applicability:** HIGH. The heads are MLPs (Linear-SiLU-Linear) — trivial to express as OV IR nodes. Tree attention is a custom mask pattern in scaled-dot-product attention; OpenVINO supports custom attention masks via `ScaledDotProductAttention` op with `attn_mask` input.

**Implementation cost:** SMALL. Per supported model: train Medusa heads (~hours on a single GPU), export head as OV IR, implement tree-mask construction in `tahoma/worker/spec_decode/`. Less complex than EAGLE because the heads don't autoregress — they're independent MLPs.

**Open hypothesis it generates for us:** Medusa-1 (frozen backbone) is the cheapest possible spec-decode: no full retraining, no autoregressive draft model, no extra forward passes for drafting. On alpha (iGPU) we expect ~1.8-2.2x decode speedup at batch=1. Critical experiment: compare Medusa-1 vs EAGLE-1 on identical model and hardware — the literature claims EAGLE wins, but EAGLE adds a transformer block to the draft path that may be relatively more costly on Intel iGPU (where small-batch matmul is less efficient). Medusa might be the better Pareto point on Lunar Lake.
