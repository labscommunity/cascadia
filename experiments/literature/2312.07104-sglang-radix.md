# SGLang / RadixAttention: KV Cache Reuse via Radix Tree (arXiv:2312.07104)

**Year / venue:** 2023.
**Headline claim:** Up to 6.4x throughput on multi-call programs (agents, RAG, chains) vs prior runtimes. RadixAttention provides automatic prefix-cache reuse.
**Mechanism:** Treat the KV-cache for all in-flight and recent sequences as one big *radix tree* keyed by the token sequence. When a new request arrives with prompt prefix P, walk the tree to find the deepest existing node matching P; reuse that node's KV blocks instead of recomputing. LRU eviction on the tree keeps memory bounded. A cache-aware scheduler reorders requests to maximize cache hits. Combined with a frontend DSL for structured generation (JSON, regex constraints) using compressed FSM decoding.

**Intel applicability:** HIGH. RadixAttention is a *memory-management algorithm*, not a kernel. Implements on top of any paged-KV-cache backend. The biggest win is for shared system prompts in chat scenarios (every request reuses the same first ~100 tokens) — exactly the workload tahoma will see in copilot deployments.

**Implementation cost:** MEDIUM. Radix tree implementation (~500 lines), token-level keying, eviction policy, scheduler integration. Needs paged KV-cache as a prerequisite.

**Open hypothesis it generates for us:** For a multi-tenant agent workload (system prompt ~200 tokens, then 5+ short user turns), RadixAttention can hit 80%+ cache reuse. On charlie, that translates to ~1.5x effective throughput because we skip prefill on the shared prefix. On alpha (single-user), the benefit is smaller but still valuable for chat-style workloads where the conversation history is reused turn-over-turn. Hypothesis: chat-history KV reuse on alpha cuts per-turn TTFT by 40-60%.
