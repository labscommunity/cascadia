# DistServe: Disaggregating Prefill and Decoding for Goodput (arXiv:2401.09670)

**Year / venue:** 2024, OSDI 2024.
**Headline claim:** 7.4x more requests/sec or 12.6x tighter SLO vs SOTA, by physically separating prefill and decode onto different hardware instances.
**Mechanism:** Observation: prefill and decode have *opposite* hardware preferences. Prefill is compute-bound and benefits from large fast tensor engines; decode is bandwidth-bound and benefits from large memory pools. Co-located on one machine they fight for resources. DistServe splits them onto different machines, using a planner to decide (a) how many prefill nodes vs decode nodes, (b) which prefill nodes feed which decode nodes, given the cluster's bandwidth topology. KV-cache transfer is layer-wise asynchronous — each layer's KV ships to the decode node as soon as it's computed.

**Intel applicability:** HIGH and *tahoma-shaped*. A heterogeneous Intel fleet has natural specialization: a Battlemage workstation makes a great prefill node (high compute via XMX), a Lunar Lake laptop makes a great decode node (lower compute is fine since decode is bandwidth-bound). Tahoma's libp2p mesh + measured-bandwidth topology graph already has the data needed to do DistServe-style placement.

**Implementation cost:** LARGE if doing it from scratch (cross-node KV transfer protocol, planner, scheduler). MEDIUM if we adopt the *idea* and start by allowing role-specialization in tahoma's master ("this worker only does prefill," "this one only does decode"), with KV-shipping reusing the existing activation-relay TCP path.

**Open hypothesis it generates for us:** On a 2-machine tahoma fleet (charlie = prefill, alpha = decode), running Llama-3-8B with disaggregated prefill should give 1.5-2.0x serving capacity vs running both on alpha alone, because we offload the compute-heavy prefill to charlie while keeping decode local. The KV transfer over Wi-Fi 6E (~1.5 Gb/s, ~150 MB/s) is the limiting factor — Llama-3-8B INT4 KV at 8K context is ~256 MB, so ~1.5 second transfer. Only profitable if prefill takes >1.5s on alpha (it does, for prompts >2K).
