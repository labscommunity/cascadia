# NITRO: LLM Inference on Intel Laptop NPUs (arXiv:2412.11053)

**Year / venue:** 2024.
**Headline claim:** First public framework for autoregressive LLM inference on Intel Meteor Lake NPU via OpenVINO. Demonstrates that the NPU (originally designed for static-shape vision models) can be made viable for dynamic-shape token generation.
**Mechanism:** Wraps OpenVINO with Python tooling that handles the static-shape limitation of the NPU runtime. Key engineering:
- Pre-export multiple static-shape variants of the transformer block (one per max-context-length bucket).
- Manage the KV-cache *outside* the NPU graph (the NPU operates on padded fixed-shape tensors, the KV is a separate allocation).
- Schedule each token's forward pass against the smallest static-shape variant that fits.
Discusses architecture modifications needed to make the LLM amenable to NPU execution: avoiding dynamic indexing, padding to fixed shapes, separating KV management from compute graph.

**Intel applicability:** N/A — this *is* an Intel paper. Direct relevance: shows the engineering pattern for getting *any* dynamic-shape model onto a static-shape execution backend, which is roughly the situation OpenVINO IR is in today for many models.

**Implementation cost:** SMALL — the techniques (static-shape buckets, externalized KV) are already used in some OV LLM exports.

**Open hypothesis it generates for us:** The NPU on Lunar Lake is faster than Meteor Lake's by ~3x and more flexible. Hypothesis: a NITRO-style static-bucket export of Llama-3-8B-INT4 on Lunar Lake NPU gives ≥1.5x decode tok/s vs the iGPU path because the NPU is purpose-built for low-precision matmul and has its own dedicated bandwidth. Worth exploring once tahoma's worker has a generic OV backend; the NPU could be the tertiary execution device after iGPU and CPU.
