# GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers (arXiv:2210.17323)

**Year / venue:** 2022, ICLR 2023.
**Headline claim:** Quantize 175B-param GPT to 3-4 bits/weight in ~4 GPU-hours, fits in a single GPU. End-to-end inference 3.25x on A100, 4.5x on A6000 vs FP16.
**Mechanism:** One-shot, layer-by-layer quantization using approximate second-order (Hessian) information. For each linear layer, GPTQ updates remaining weights in a column-by-column sweep to compensate for the rounding error introduced by the previously quantized columns — the inverse Hessian directs which weights to update and by how much. Only requires forward passes through a small calibration set (no backprop). Predecessor of AWQ; widely supported by inference kernels (`autogptq`, `exllama`, OpenVINO).

**Intel applicability:** HIGH. GPTQ-quantized models load directly into OpenVINO via `optimum-intel`. Common 4-bit weight format (group-size 128, sym/asym) is what OpenVINO expects.

**Implementation cost:** TRIVIAL — pre-existing pipeline.

**Open hypothesis it generates for us:** GPTQ vs AWQ: for the typical Llama-class model on Intel iGPU, perplexity gap is small (≤0.1 PPL). The kernel cost is identical. The interesting question is whether the *combined* AWQ → GPTQ refinement produces a meaningful win. Anecdotally yes (~0.05 PPL); worth a one-time test on charlie to decide whether tahoma's default exporter chains both or just one.
