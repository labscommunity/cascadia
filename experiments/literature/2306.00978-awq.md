# AWQ: Activation-aware Weight Quantization (arXiv:2306.00978)

**Year / venue:** 2023, MLSys 2024 (best paper).
**Headline claim:** >3x over HF FP16 on desktop and mobile GPUs. Negligible accuracy loss at 4-bit weight-only. Enables Llama-2-70B on a mobile GPU.
**Mechanism:** Weight-only quantization to INT4. Insight: only ~1% of weight channels are "salient" (those that produce the activations with the largest magnitudes). Identify salient channels by *activation* statistics (not weight magnitudes — that's the surprising bit). Then apply a per-channel scaling transformation: multiply salient weights by `s` and the corresponding activation by `1/s`, mathematically equivalent but compresses the salient weights into a more quantization-friendly range. No backprop, no gradient — fully calibration-based. Paired with the TinyChat kernel that fuses dequant + matmul.

**Intel applicability:** HIGH. The AWQ algorithm is hardware-neutral; OpenVINO's NNCF (Neural Network Compression Framework) explicitly added AWQ support in OV 2024.0, and AWQ-quantized models in OpenVINO IR ship from `optimum-intel`. The TinyChat kernel doesn't apply (CUDA), but OV has its own fused INT4-weight-with-FP16-activation matmul on Arc GPUs.

**Implementation cost:** TRIVIAL — `optimum-intel` + `nncf` produces AWQ-INT4 OpenVINO IR with one CLI call. Tahoma's exporter should default to AWQ rather than naive RTN INT4.

**Open hypothesis it generates for us:** On charlie, AWQ-INT4 vs naive INT4-RTN should give equal or better tok/s (kernel is the same, the only difference is which weights got quantized to which bins) but ~30-50% lower perplexity. On alpha (memory-bound), AWQ should give the *same* tok/s and effectively unlock running Llama-3-13B in 8GB iGPU memory at usable quality. Treat AWQ as the default quantizer; do not experiment with naive RTN.
