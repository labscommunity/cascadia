# MARLIN: Mixed-Precision Auto-Regressive LIN-ear kernel (arXiv:2408.11743)

**Year / venue:** 2024.
**Headline claim:** Near-ideal 4x speedup on FP16 × INT4 GEMM up to batch 16-32. End-to-end LLM inference: 2.8x with vLLM integration. Sustains gains at batch 64-128.
**Mechanism:** A custom CUDA kernel for the W4A16 case (4-bit weights, 16-bit activations) optimized for the *autoregressive batched* regime where prior INT4 kernels (designed for batch=1) lose their speedup. Combines: asynchronous global-to-shared memory loads (cp.async), software pipelining of dequant + matmul stages, careful warp scheduling so dequant happens during the previous tile's matmul. Bespoke quantization layout: weights pre-permuted at quantize time into the exact shape the inner kernel wants, eliminating runtime swizzling.

**Intel applicability:** MEDIUM. The kernel is CUDA-only, but the *insights* are architecture-portable: (1) async loads + double-buffered dequant + matmul should also win on Intel XMX; (2) pre-permuting INT4 weights to match the matmul's preferred layout removes runtime overhead; (3) batch-aware kernel selection (one binary per batch range). OpenVINO's INT4 matmul team has implemented similar ideas, but it's worth verifying that the OV kernel sustains its W4A16 advantage at batch 16+ (this is the regime MARLIN targets).

**Implementation cost:** N/A as a port (CUDA kernel). SMALL as a *benchmarking exercise* — measure OV's W4A16 throughput vs theoretical peak across batch sizes 1, 4, 16, 64. If it falls off a cliff at batch >4, file as an upstream OV issue with MARLIN as the reference.

**Open hypothesis it generates for us:** The interesting Intel-side question is whether OV's W4A16 GEMM matches MARLIN's curve. Concrete experiment: on charlie (Battlemage), measure W4A16 GEMM throughput as a function of batch (1, 2, 4, 8, 16, 32, 64) for typical Llama hidden sizes (4096, 11008). Plot achieved-TFLOPS vs batch and compare to memory-bound prediction. If achieved-TFLOPS plateaus below memory roof at batch >4, OV's kernel is leaving performance on the table.
