# QuIP#: Even Better LLM Quantization with Hadamard Incoherence and Lattice Codebooks (arXiv:2402.04396)

**Year / venue:** 2024, ICML 2024.
**Headline claim:** State-of-the-art at ≤4 bits/weight, viable 2-bit quantization. Llama-2-70B at 2 bits with manageable perplexity loss.
**Mechanism:** Three pieces. (1) *Randomized Hadamard transform* applied to weights and Hessian to make their distributions "incoherent" (closer to spherically Gaussian, fewer outliers). Critically the Hadamard is a structured rotation that fuses cheaply into the layer at inference time. (2) *Vector quantization on the E8 lattice* — 8-dimensional codebook giving optimal sphere packing, encoded as 8 bits per 8-dim vector → 1 bit/weight average. (3) Post-quantization fine-tune to recover lost fidelity.

**Intel applicability:** MEDIUM. The Hadamard transform is portable (it's a fixed orthogonal matmul, free at inference once fused). The E8 lattice decode is a small lookup-table per group of 8 weights — implementable on Intel via a custom OV op or as a CPU pre-decompression step. INT2 matmul kernels are not yet a native path on Intel iGPU/Arc (XMX supports INT4/INT8). The 2-bit weights would have to be unpacked to INT4 before matmul, which leaves the *memory* benefit (4x less weight traffic) but not the compute benefit.

**Implementation cost:** MEDIUM. Hadamard fusion in the IR exporter is a few hundred lines. E8 codebook decode is the harder part — need a custom OV operator unless we accept CPU-side decode (which kills throughput). Realistic path: implement INT2 → INT4 unpack in a CPU prologue per layer load, accept ~1.4x decode speedup from memory traffic alone.

**Open hypothesis it generates for us:** On alpha (memory-bound, 70 GB/s LPDDR5X), going from W4 to W2 gives a theoretical 2x bandwidth reduction. Realistic: 1.5-1.8x decode tok/s if we can do efficient on-device unpack. Concrete experiment: implement a simple INT2 → INT4 unpack pass and run Llama-3-8B-QuIP# on alpha. If it gives ≥1.5x over AWQ-INT4, prioritize a proper kernel.
