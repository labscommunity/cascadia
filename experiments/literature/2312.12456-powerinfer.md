# PowerInfer: Fast LLM Serving with Consumer-grade GPU (arXiv:2312.12456)

**Year / venue:** 2023.
**Headline claim:** Up to 11.69x over llama.cpp on consumer hardware. Achieves 82% of A100's tok/s on a single RTX 4090 for OPT-30B.
**Mechanism:** Exploits the empirical observation that LLM activations follow a *power-law sparsity*: a small set of "hot" neurons fire on most inputs, while "cold" neurons rarely fire (especially after the SiLU/GELU non-linearity in FFN gating). PowerInfer profiles which neurons are hot per layer offline, then at inference: (a) keeps hot neurons resident on GPU, (b) keeps cold neurons on CPU, (c) uses a small predictor network to decide at runtime which cold neurons to actually compute (skipping the rest entirely). Custom sparse matmul kernels for the GPU side; standard CPU matmul for the small cold set. Cuts both memory footprint and compute.

**Intel applicability:** HIGH and *uniquely Intel-relevant*. The hot/cold split aligns *perfectly* with Intel HETERO: hot neurons → iGPU/Arc, cold neurons → CPU AMX path. Intel's CPU is genuinely good (especially with AMX) — better than the AMD/CPU baseline PowerInfer assumed — so the hybrid Pareto on Intel should be even better than the published NVIDIA numbers.

**Implementation cost:** LARGE. Need: (a) offline neuron profiling + clustering, (b) a predictor net per layer, (c) runtime split of FFN execution between iGPU and CPU, (d) a sparse FFN kernel for the GPU side. The OV HETERO plugin already supports CPU+GPU op placement, so the orchestration layer is mostly free; the predictor and sparse kernel are the new work.

**Open hypothesis it generates for us:** The entire PowerInfer thesis (sparse activation makes hybrid CPU+GPU profitable) maps onto Intel HETERO with the right adaptation. Concrete experiment: profile a Llama-3-8B-INT4 on alpha to measure FFN sparsity in practice. If the top-30% hot neurons account for >70% of forward activations, then a HETERO split with hot on iGPU and cold on CPU should give a 1.5-2x decode speedup. If sparsity is lower (e.g. <50%), the technique doesn't apply to modern post-2024 LLMs (which use SwiGLU, not ReLU — sparsity is reportedly lower).
