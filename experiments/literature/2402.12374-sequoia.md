# Sequoia: Scalable, Robust, and Hardware-aware Speculative Decoding (arXiv:2402.12374)

**Year / venue:** 2024.
**Headline claim:** Up to 4.04x on Llama2-7B (A100), 3.84x on Llama2-13B, 9.96x on Llama2-70B with offloading (L40). Robust across decoding temperatures.
**Mechanism:** Three-part contribution. (1) A *dynamic-programming algorithm* for computing the optimal token-tree shape given a hardware cost model and a draft-acceptance distribution — formally maximizes E[accepted tokens] subject to a verify-cost budget. (2) A novel sampling-and-verification procedure that achieves higher acceptance at high temperatures than SpecInfer/Medusa. (3) A *hardware-aware tree optimizer* that profiles the verify kernel on the target hardware and selects tree size/depth automatically — the same algorithmic improvement yields different optimal trees on different GPUs.

**Intel applicability:** HIGH and arguably *most* relevant of the spec-decode papers because of the hardware-aware optimizer. The verify cost on Intel iGPU vs Battlemage vs A100 differs by orders of magnitude in the small-batch regime, so a one-size-fits-all tree shape is wrong. Sequoia's optimizer is a direct fit for our heterogeneous fleet.

**Implementation cost:** MEDIUM. The DP solver is ~300 lines; the cost-profiling pass needs to run a small grid of (tree_size, tree_depth) combinations and time them on each device. Once we have `Engine.measure_verify_cost(tree_shape)`, the rest is pure Python.

**Open hypothesis it generates for us:** Sequoia's hardware-aware optimizer should pick *deeper, narrower* trees on Intel iGPU than on NVIDIA, because Intel iGPU verify cost grows more steeply with tree width (more parallel compute) than depth (more sequential ops). Concrete experiment on alpha: run the DP solver with measured `verify_cost(width, depth)` and check whether the optimal `(width, depth)` differs from NVIDIA defaults by >1.5x in either dimension. If yes, this is a free 20-30% on top of any underlying spec-decode method.
