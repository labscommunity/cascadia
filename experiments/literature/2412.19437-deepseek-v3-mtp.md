# DeepSeek-V3: MTP, MLA, DualPipe, EP (arXiv:2412.19437)

**Year / venue:** 2024.
**Headline claim:** 671B-param MoE (37B activated) trained for 2.788M H800 GPU-hours. Inference: MTP modules give ~1.8x decode speedup via spec-decode (lossless when used as a verifier).
**Mechanism:** Several composable inference innovations:
- **MLA (Multi-head Latent Attention)**: cross-layer KV-cache compression to a low-rank latent vector, reducing KV memory by 93% vs MHA while preserving quality (better than GQA on the size/quality Pareto). See the dedicated DeepSeek-V2 paper (arXiv:2405.04434) for details.
- **MTP (Multi-Token Prediction)**: training-time auxiliary heads that predict the next K tokens; at inference these heads can be reused as draft heads for spec-decode (≈ EAGLE/Medusa but baked into pretraining).
- **DualPipe**: pipeline parallelism schedule that overlaps the forward and backward bubbles via a "fold" pattern, reducing PP-bubble idle time. Inference-relevant analogue: forward-only DualPipe schedule for sharded inference reduces stage-to-stage idle.
- **DeepEP / Expert Parallelism**: efficient all-to-all over IB; each token only routes to its activated experts.

**Intel applicability:** MIXED.
- MLA: HIGH. Pure architectural change in the model — applies to any inference engine. OpenVINO would represent it as a slightly different attention block. Cuts KV memory dramatically — huge for alpha.
- MTP: HIGH. The MTP heads are exactly Medusa-style — already a portable concept.
- DualPipe (forward-only variant): MEDIUM. The schedule applies to any pipeline-parallel runtime. Tahoma's pipeline-parallel design could adopt this directly.
- DeepEP: LOW. Assumes IB / NVLink. On a tahoma libp2p mesh the bandwidth/latency profile is different and EP would need to be much cheaper per-call.

**Implementation cost:** Variable. MLA support in OV depends on whether we can convince OV to fuse the latent compression as a single op. MTP head reuse for spec-decode is mostly model-loading work. DualPipe forward-only schedule is a scheduler change in tahoma/master.

**Open hypothesis it generates for us:** MLA is the single most interesting structural change for Intel iGPU because it directly addresses the bandwidth bottleneck on Lunar Lake. Hypothesis: a small-MLA model (e.g. a 7B model retrofitted to MLA via the TransMLA / arXiv:2502.07864 method) on alpha gives 1.4-1.8x decode tok/s vs the same model with GQA, due to ~6x KV traffic reduction.
