# EAGLE-2: Faster Inference of Language Models with Dynamic Draft Trees (arXiv:2406.16858)

**Year / venue:** 2024, EMNLP 2024.
**Headline claim:** 3.05x-4.26x speedup on Vicuna/LLaMA-2-Chat, an additional 20-40% over EAGLE-1. Single-GPU speculative decoding, batch=1.
**Mechanism:** EAGLE-1 used a *static* draft tree shape (e.g. always speculate the top-K children at each depth). EAGLE-2 observes that the draft model's own confidence score is a calibrated proxy for acceptance probability, and uses it to dynamically allocate the draft budget — wide where the draft is sure, deep where it has high confidence on a single path. Implemented as: (a) global token expansion using accumulated confidence as a priority queue, and (b) reranking to keep only the top-N highest-value tokens in the verified batch.

**Intel applicability:** HIGH. Pure CPU-side scheduling change on top of an EAGLE-1 deployment — no kernels touched. Acceptance-probability calibration may need re-fitting on Intel hardware because the optimal tree shape depends on per-token verification cost, which differs from NVIDIA on a per-architecture basis.

**Implementation cost:** SMALL given EAGLE-1 is already in tahoma. Add a `DynamicDraftTreeBuilder` that takes draft logits and a configurable token budget, emits the tree and corresponding attention mask. ~200 lines of Python.

**Open hypothesis it generates for us:** EAGLE-2's "best tree budget" depends on the ratio of draft-step cost to verify-step cost. On Intel iGPU (alpha, Arc 140V) the verifier is *relatively* slower than on NVIDIA because OpenVINO matmul throughput is lower per unit HBM, so we should see larger optimal tree budgets and higher acceptance gains. Hypothesis: a well-tuned dynamic tree on alpha will produce >35% gain over a static tree, vs the ~25% reported on NVIDIA.
