# QuaRot: Outlier-Free 4-Bit Inference in Rotated LLMs (arXiv:2404.00456)

**Year / venue:** 2024, NeurIPS 2024.
**Headline claim:** Llama-2-70B at W4A4KV4 with only 0.47 PPL increase on WikiText-2 and 99% of zero-shot perf retained. 3.33x prefill speedup, 3.89x decode memory savings.
**Mechanism:** *End-to-end* 4-bit inference (weights, activations, *and* KV cache) by removing outlier features via *Hadamard rotations* applied to the residual stream and FFN/attention activations. Because Hadamard is orthogonal, fusing it into adjacent linear layers yields a mathematically equivalent network with no outliers. The rotated tensors quantize cleanly. KV-cache also gets rotated, allowing INT4 storage. End-to-end this means *every* matmul is INT4 × INT4 (not the usual INT4 × FP16), unlocking native INT4 tensor-core throughput.

**Intel applicability:** HIGH-MEDIUM. The rotation idea is fully portable. *Whether* you get the speedup depends on whether the target hardware has INT4 × INT4 matmul. Intel Battlemage XMX engines support INT4 weight × INT8 activation in the high-throughput path; full INT4 × INT4 is not yet a published path on Arc. So on Battlemage we'd get the *memory* benefit (4x less activation + KV traffic) but realistically be running W4A8 not W4A4. Still a big win on activation traffic and KV.

**Implementation cost:** MEDIUM. Hadamard fusion into linear layers is straightforward (one matmul per layer at export time). The harder part: making OV's PagedAttention support INT4 KV-cache (not all OV versions do).

**Open hypothesis it generates for us:** Combine QuaRot's Hadamard rotation with W4A8 SmoothQuant on Battlemage. Hypothesis: W4A8KV4 with QuaRot rotation matches W4A16 perplexity to within 0.2 PPL while giving 2-3x decode throughput improvement on charlie due to KV traffic reduction. The rotation also makes the activation outliers manageable, which would let SmoothQuant's `s_j` factors be smaller (less weight-side dynamic range eaten up).
