# Hydra: Sequentially-Dependent Draft Heads for Medusa Decoding (arXiv:2402.05109)

**Year / venue:** 2024, COLM 2024.
**Headline claim:** Up to 1.31x over Medusa, 2.70x over autoregressive — same hardware, same base model.
**Mechanism:** Drop-in replacement for Medusa's draft heads. Medusa's heads predict positions +1, +2, +3, ... independently from the same base hidden state, which is statistically suboptimal because the head for position +3 should be conditioned on the predicted token at +1 and +2. Hydra makes the head at depth k take as input both the base hidden state and the embeddings of the k-1 previously sampled draft tokens. "Hydra++" adds: deeper MLPs in heads, teacher distillation, and an extra transformer decoder layer to encode the verified prefix. The draft path is still parallel-launchable because all heads execute given the same base hidden — just with augmented conditioning.

**Intel applicability:** HIGH. Same export and runtime story as Medusa; only the head graph changes. Acceptance rate goes up (more accepted tokens per verify pass), so the verify-pass cost is amortized better — exactly the regime Intel iGPU benefits from (verify is the expensive op, drafting is cheap).

**Implementation cost:** SMALL on top of Medusa. The head's input changes from `(hidden,)` to `(hidden, draft_emb_1, ..., draft_emb_{k-1})`. Tree-attention mask construction is unchanged.

**Open hypothesis it generates for us:** Hydra's mean accepted length (MAL) goes up by ~20% over Medusa. On a hardware platform where verify is expensive vs draft (Intel iGPU), every +1 MAL is worth more wall-clock than on NVIDIA. Hypothesis: Hydra's *relative* gain over Medusa on alpha will be 1.4-1.5x rather than the 1.31x reported on NVIDIA. Worth A/B testing in the same harness as Medusa-1.
