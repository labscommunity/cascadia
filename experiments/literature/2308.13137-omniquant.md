# OmniQuant: Omnidirectionally Calibrated Quantization for LLMs (arXiv:2308.13137)

**Year / venue:** 2023, ICLR 2024 (spotlight).
**Headline claim:** Solid quality at W4A4, W6A6, W4A16, W3A16, W2A16 across LLaMA-2 7B-70B, calibrated on a single A100 in 1-16 hours.
**Mechanism:** Bridges PTQ and QAT. Freezes the weights at full precision. Adds two sets of *learnable* parameters per layer: (a) Learnable Weight Clipping (LWC) — per-channel weight clip thresholds learned to minimize block-wise reconstruction error; (b) Learnable Equivalent Transformation (LET) — per-channel scale factors that play the same role as SmoothQuant's `s_j` but are *learned* rather than hand-fitted from activation stats. Optimization is block-by-block (one transformer block at a time) with a small calibration set, so memory cost stays low.

**Intel applicability:** HIGH. The output is a quantized model, not a runtime — once quantized, deploys via standard OV INT4/INT8 paths. Particularly useful for *low-resource* quantization (W3A16, W2A16) where vanilla AWQ/GPTQ start to crack.

**Implementation cost:** TRIVIAL for *using* OmniQuant-quantized checkpoints. SMALL for running it (a 7B model on a single 16GB GPU in a few hours).

**Open hypothesis it generates for us:** OmniQuant's main edge is at *aggressive* bitwidths (W3, W2). For Lunar Lake (alpha) where memory is the binding constraint and LPDDR5X bandwidth is the throughput limiter, going W4→W3 saves 25% bandwidth. Hypothesis: W3A16 OmniQuant on alpha gives ~1.2x decode speedup over W4A16 AWQ at similar perplexity. Worth a back-to-back if we can budget the offline quantization time.
