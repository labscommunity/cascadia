# SmoothQuant: PTQ for INT8 W8A8 LLMs (arXiv:2211.10438)

**Year / venue:** 2022, ICML 2023.
**Headline claim:** 1.56x speedup, 2x memory reduction at W8A8 with negligible accuracy loss. Enables 530B model on a single node.
**Mechanism:** Activation outliers — a few channels with magnitudes 100x larger than the rest — make INT8 *activation* quantization brittle. SmoothQuant migrates this difficulty offline: scale down the high-outlier activation channels by `s_j` and scale up the corresponding weight channels by `s_j`. Mathematically equivalent (for `Y = XW`, scaling `X[:,j]` by `1/s_j` and `W[j,:]` by `s_j` is a no-op). After this transform, both X and W quantize cleanly to INT8. Needs only calibration data, no training.

**Intel applicability:** HIGH. INT8 GEMM (W8A8) is the *native fast path* on Intel CPUs (AMX), Intel iGPU (DP4A / DP8A on Xe), and Battlemage (XMX matrix engines). SmoothQuant is a no-brainer on Intel because INT8 fast paths are much wider than INT4 ones — INT4 weight + FP16 activation requires a dequantize-and-matmul fused kernel, while W8A8 maps to a single XMX/AMX instruction.

**Implementation cost:** SMALL. NNCF supports SmoothQuant. Tahoma's exporter just needs a flag.

**Open hypothesis it generates for us:** On Intel iGPU and Arc B580, W8A8 SmoothQuant might outperform W4A16 AWQ at small batch despite using 2x the weight memory, because the W4A16 dequant overhead and the FP16 activation traffic combine to dominate. Concrete experiment on charlie: benchmark Llama-3-8B at W4A16-AWQ vs W8A8-SmoothQuant for batch=1 decode. If W8A8 wins, the default for Battlemage should be W8A8 even though everyone defaults to W4A16 on NVIDIA. This would be a notable Intel-specific finding.
